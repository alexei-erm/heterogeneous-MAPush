### Contact-Force Gating for go1push_mid (HAPPO)

Ported the contact-force-based dual-push balance mechanism from `go1_push_vel_wrapper.py` to `go1_push_mid_wrapper.py`, controlled by `--contact_force_gating` flag.

**Problem:** In heterogeneous HAPPO (e.g. Go1 + Anymal), the weaker agent freeloads — it gets team reward without contributing. The velocity task already had a contact-force gating mechanism; this session ports it to the goal-based mid task.

**Mechanism:**
- Reads `contact_forces` tensor from Isaac Gym (horizontal XY forces on non-foot bodies)
- Mass-normalizes contributions per agent
- Computes balance ratio: `min(contributions) / max(contributions)` (1.0 = balanced, 0.0 = one agent idle)
- Gates rewards: `reward *= alpha + (1 - alpha) * balance`
- 5.0N threshold: no gating when nobody is pushing

**Gated rewards:** `push_reward` and `distance_to_target_reward` (the rewards a freeloader benefits from without contributing). NOT gated: `approach_reward`, `ocb_reward` (positioning incentives), `reach_target_reward` (too sparse).

### Usage

```bash
# With contact-force gating (alpha=0.3 -> freeloader gets max 30% of gated rewards)
python HARL/harl_mapush/train.py \
  --contact_force_gating True \
  --contact_force_gating_alpha 0.3 \
  --agent0 go1 --agent1 anymal_c \
  --use_concat_agent_observations_critic True \
  --mapush_og_rewards_teamified True \
  --num_env_steps 100000000

# Without gating (default, no change to existing behavior)
python HARL/harl_mapush/train.py --exp_name baseline
```
